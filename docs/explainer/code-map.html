01システム構成

Mermaid はブラウザで動く JavaScript ライブラリで、サーバーやデータベースを持ちません。外から呼ばれる入口は mermaid.ts だけで、そこから先は「前処理 → 図の判定 → 図ごとのコード → 共通の描画部品」と流れ、最後にサニタイズ済みの SVG 文字列を返します。

配布物

ESM と IIFE

mermaid.core.mjs（依存を外に出す ESM）、mermaid.esm.mjs、mermaid.min.js（IIFE）を esbuild で作る。図は chunk に分かれて遅延読込される。

injected

ビルド時の定数

injected.includeLargeFeatures が偽の tiny ビルドでは、mindmap・architecture・flowchart-elk・cose-bilkent・elk を登録しない。injected.profiling は計測用。

開発

ローカルで動かす

pnpm dev で .esbuild/server.ts が :9000 で起動し、demos/ の HTML で確かめる。ドキュメントは pnpm --filter mermaid docs:dev。

03レイヤー構成

3つのまとまりに分けて見ると、どこを直せばよいかが決まります。

① 本体の流れ

図の種類を知らない

  1. mermaid.ts公開 API。キューで直列化
  2. mermaidAPI.tsrender の段取り・CSS・サニタイズ
  3. Diagram.ts判定・遅延読込・parse
  4. diagram-api/detector の登録簿と判定

ここを直すと全部の図に影響する。

② 図ごとの5点セット

diagrams/<種類>/

  1. *Detector.tsid・正規表現・loader
  2. parser.jison／Langium／Chevrotain
  3. *Db.tsパース結果の保持・getData()
  4. *Renderer.tsdraw()。共通レンダラーか D3
  5. styles.tsテーマ変数 → CSS

ここを直すとその図だけに影響する。

③ 共通の部品

rendering-util/ ほか

  1. render.tsレイアウトの登録と選択
  2. layout-algorithms/prepare→measure→layout→paint
  3. rendering-elements/形・線・枠・矢じり・交点
  4. themes/・styles.tsテーマ変数と CSS の組み立て

ここを直すと共通レンダラーを使う図（フローチャート・状態・クラス・ER・要求・マインドマップ・エージェントフロー・ユースケース）に影響する。

描き方は2系統箱と線の図は db.getData() で LayoutData に変えて共通レンダラーへ。シーケンス図・ガント・円グラフ・チャート類などは、renderer が D3 で SVG を直接組み立てる（座標計算も図のコード内）。

05データの形

図ごとのコードと本体をつなぐ「約束ごと」の型です。データベースの代わりに、この型を押さえると全体が読めます。

diagram-api/types.ts

DiagramDefinition

interface DiagramDefinition {
  db: DiagramDB;          // 読んだ結果をためる
  parser: ParserDefinition; // parse(text)
  renderer: DiagramRenderer; // draw(text, id, ver, diag)
  styles?: (opts) => string; // 図用 CSS
  init?: (config) => void;
}

各図の *Diagram.ts（または diagram.ts・*-definition.ts）がこれを export する。detector の loader が { id, diagram } を返す。

diagram-api/types.ts

getAccDescription()  setDirection()
setDiagramId()  bindFunctions(el)
setErrorMessage()  getConfig()

// 箱と線の図は getData(): LayoutData も持つ

Jison の図は parser.yy に db がそのまま入り、文法のアクションから db のメソッドが呼ばれる。

rendering-util/types.ts

LayoutData

{
  nodes: Node[];  // id・label・shape・isGroup・parentId・cssClasses …
  edges: Edge[];  // start・end・arrowTypeEnd・label・curve …
  config: MermaidConfig;
  type, direction, layoutAlgorithm,
  nodeSpacing, rankSpacing, markers, diagramId
}

共通レンダラーの入力。レイアウトは x・y・width・height・points を書きこんで返す。サブグラフは isGroup のノードと parentId で表す。

mermaidAPI.ts

RenderResult

{
  svg: string;            // サニタイズ済み
  diagramType: string;    // 'flowchart-v2' など
  bindFunctions?: (el) => void; // click など
}

mermaid.parse() は描かずに { diagramType, config } を返す（失敗時は例外、suppressErrors なら false）。

08横断的な仕組みの場所

ビルド

esbuild で ESM・IIFE・tiny を作る。.jison と設定スキーマもここで変換

開発サーバー

pnpm dev（ポート 9000）。demos/ のページで確かめる

Langium の文法

packages/parser。langium generate で generated/ を作る

設定の型

schemas/config.schema.yaml から config.type.ts を生成

ドキュメント

src/docs が原稿。docs:build で docs/ を生成

ユニットテスト

ソースの隣の *.spec.ts（Vitest）

画像比較のテスト

e2e/diagrams の .mmd を描いて撮る（Playwright・Argos）

変更履歴

PR ごとに changeset を足す

ログ・ユーティリティ

どこからでも使う小物

よくある変更の入口

新しい図の種類を足す

  1. diagrams/<名前>/ に detector・parser・db・renderer・styles と定義ファイルを作る
  2. 文法は Langium なら packages/parser/src/language/<名前>/ と parse.ts の initializers に追加
  3. diagram-orchestration.ts の registerLazyLoadedDiagrams に detector を足す（順番に注意）
  4. 設定は config.schema.yaml、ドキュメントは src/docs/syntax/<名前>.md
  5. e2e/diagrams/<名前>/ にお手本の .mmd を置く

フローチャートに形を足す

  1. rendering-elements/shapes/ に形の関数（描画と intersect）を作る
  2. shapes.ts の一覧に name・shortName・aliases を登録する
  3. ドキュメントの形の一覧と e2e のお手本を足す

設定項目を足す

  1. config.schema.yaml に項目・型・default・説明を書く
  2. pnpm --filter mermaid types:build-config で config.type.ts を作り直す
  3. 使う側で getConfig() から読む。安全に関わるなら secure の既定値に加える

テーマ変数を足す

  1. theme-base.js などの各テーマで、既存の色から計算して既定値を決める
  2. 図の styles で options.<変数名> を CSS に使う
  3. テーマのドキュメント（theming.md）に追記する
