01システム構成

Mermaid はブラウザで動くライブラリ。サーバーもデータベースもありません。

受付（mermaid.ts）から順に係へ渡し、最後に安全な SVG を返します。

📦配るファイルESM（mermaid.core.mjs など）と IIFE（mermaid.min.js）。図ごとに分割して、使うときに読みこむ
🪶軽量版 tinyinjected.includeLargeFeatures が偽。マインドマップ・アーキテクチャ図・ELK などを外す
🧪手元で動かすpnpm dev で :9000 に開発サーバー。demos/ のページで確かめる

02フォルダの地図

本体は packages/mermaid/src。いちばん大きいのは図ごとのフォルダ diagrams/ です。

03レイヤー構成

どの段を直すかで、影響する範囲が変わります。

描き方は2系統。箱と線の図は共通レンダラー、それ以外は図ごとに D3 で直接描きます。

05データの形

テキストは、この順に形を変えながら進みます。各段階の型の中身は下の表のとおりです。

DiagramDefinition：図1種類ぶんの定義

項目型役目
dbDiagramDBパース結果をためる。Jison の図では parser.yy にそのまま入る
parserParserDefinitionparse(text) で文を読み、db に詰める
rendererDiagramRendererdraw(text, id, version, diagram) で SVG を描く
styles?(options) => stringテーマ変数から図用の CSS 文字列を作る
init?(config) => voidparse の前に呼ばれ、図ごとの設定を整える

各図の *Diagram.ts（diagram.ts・*-definition.ts）が export する。detector の loader が { id, diagram } を返す。

ParserDefinition・DiagramRenderer

項目型役目
parse(text) => void | Promise文を読む。Langium の図は @mermaid-js/parser の parse() を await する
parser?{ yy: DiagramDB }Jison の生成パーサーだけが持つ。Diagram.fromText が yy = db を入れる
drawDrawDefinition描画の本体。共通レンダラーを使う図は中で db.getData() と render() を呼ぶ
getClasses?(text, diagram) => MapclassDef の一覧を返し、createUserStyles が CSS にする

DiagramDB：パース結果を持つ側（すべて任意）

項目型役目
clear() => voidparse の前に呼ばれ、前回の結果を消す
setDiagramTitle・getDiagramTitle(title) / () => stringtitle。共通処理は diagrams/common/commonDb.ts
setAccTitle・getAccTitle(title) / () => string読み上げ用のタイトル（accTitle）
setAccDescription・getAccDescription(desc) / () => string読み上げ用の説明（accDescr）
setDirection・getDirection(dir) / () => stringTB・LR などの向き
setDiagramId(id) => voidSVG の id を受け取り、要素の id の衝突を防ぐ
bindFunctions(element) => voidclick などのイベントを SVG に付ける。RenderResult でそのまま返る
setErrorMessage(message) => voiderror 図に、実際のエラー内容を表示させる
getData() => LayoutData箱と線の図だけが持つ。共通レンダラーへ渡すデータを作る

LayoutData：共通レンダラーへの入力

項目型役目
nodesNode[]箱。サブグラフは isGroup: true のノードで、子は parentId で親を指す
edgesEdge[]線。start・end でノードの id を指す
configMermaidConfigその図の設定（getConfig() の結果）
typestringflowchart-v2 などの図の種類。renderer が足す
layoutAlgorithmstringdagre・elk など。getRegisteredLayoutAlgorithm() で決める
directionstringTB・LR など
nodeSpacing・rankSpacingnumberノードどうし・段どうしの間隔
markersstring[]使う矢じりの種類（point・circle・cross）
diagramIdstringSVG の id。render() がノードの domId の前に付ける

Node：箱（主な項目）

項目型役目
idstringノードの名前（A など）
labelstring表示する文字
shapeShapeID形（rect・diamond など）。rendering-elements/shapes.ts の名前
isGroup・parentIdboolean / stringサブグラフかどうかと、親のグループ
cssClasses・cssStylesstring / string[]classDef・style で付けた見た目
link・tooltipstringclick で付けたリンクとツールチップ
width・heightnumbermeasure で測った大きさ
x・ynumberlayout が書きこむ中心の座標
domIdstringSVG の要素の id

Edge：線（主な項目）

項目型役目
idstring線の id
start・endstringつなぐノードの id
labelstring線の上の文字
arrowTypeStart・arrowTypeEndstring両端の矢じり（arrow_point など）
thickness・patternstring太さ（normal・thick）と線の種類（実線・点線）
curvestring曲線の種類（basis・linear など）
pointsPoint[]layout が書きこむ折れ点の座標

RenderResult・ParseResult：外に返すもの

項目型役目
svgstringrender() の結果。サニタイズ済みの SVG 文字列
diagramTypestringflowchart-v2 などの図の種類（render・parse の両方）
bindFunctions?(element) => voidSVG を入れた要素に渡すと、click などが動くようになる
configMermaidConfigparse() の結果。frontmatter とディレクティブから読み取った設定

mermaid.parse() は描かずに ParseResult を返す。失敗すると例外、suppressErrors: true なら false。

設定の重ね合わせ

層入れる関数中身
defaultConfigdefaultConfig.tsconfig.schema.yaml の default から生成された既定値。凍結（freeze）されている
siteConfiginitialize() → setSiteConfigページ作者の設定。secure に入ったキーはここでしか変えられない
directivesaddDirective()frontmatter の config: と %%{init}%%。sanitize() で secure キー・__ 始まり・<>・url(data: を除いてから重ねる
currentConfiggetConfig()site＋directives。テーマ名が変わったら themeVariables を再計算。図の種類ごとの見た目（theme・look・layout）は setDiagramConfigScope で render の間だけ効く
