03係の分担

仕事を係に分けています。

新しい図を足すときは、5人組を1チーム増やすだけ。

コードで見ると：担当チームは「オブジェクト」1つ
// diagrams/pie/pieDiagram.ts（円グラフの担当チーム）
export const diagram = {
  parser,    // 読み取り係
  db,        // 記録係
  renderer,  // 描き係
  styles,    // 色係
};
// 見分け係は、別のファイル（pieDetector.ts）にいる

5人組は、オブジェクトのプロパティとしてまとめられています。進行役は diagram.parser や diagram.renderer を呼ぶだけなので、どの図でも同じ手順で動かせます。

04図ができるまで

8つのステップで、文字が図になります。

コードで見ると：順番待ちの列は「配列」
const executionQueue = [];   // 順番待ちの列

function render(id, text) {
  executionQueue.push(() => 描く(id, text));  // 列の最後に並ぶ
  executeQueue();
}

async function executeQueue() {
  while (executionQueue.length > 0) {
    const f = executionQueue.shift();   // 先頭を取り出す
    await f();                          // 終わるまで待つ
  }
}

mermaid.ts のコードを短くしたものです。push で配列の最後に入れて、shift で先頭から取り出すので、頼んだ順に1つずつ処理されます。

05何の図か当てる

1行目の言葉で図の種類が決まります。

候補は 37 種類。決まった図の係だけを呼んできます。

コードで見ると：見分けるのは「for 文と if 文」
// diagram-api/detectType.ts（短くしたもの）
function detectType(text) {
  for (const [key, { detector }] of Object.entries(detectors)) {
    if (detector(text)) {   // 見分け係に聞く
      return key;            // 最初に「はい」と言った図に決定
    }
  }
  throw new UnknownDiagramError('どの図にも当てはまりません');
}

// フローチャートの見分け係（flowDetector-v2.ts）
const detector = (txt) => /^\s*(graph|flowchart)/.test(txt);

return した時点でループが終わるので、名簿で先に並んでいる図が勝ちます。見分け係は、文字列が正規表現に合うかを true／false で返す関数です。

06文を読む

A名前
[注文]四角
-->矢印
B名前
{在庫ある?}ひし形

パーサーが、文を部品に分けます。

分けた部品は記録係のノートにたまります。

コードで見ると：記録係は「Map と配列」
// diagrams/flowchart/flowDb.ts（とても短くしたもの）
class FlowDB {
  vertices = new Map();   // ノードの一覧（名前 → 中身）
  edges = [];              // 矢印の一覧

  addVertex(id, text, type) {
    this.vertices.set(id, { id, text, type });
  }
  addLink(start, end, linkData) {
    this.edges.push({ start, end, ...linkData });
  }
}

// パーサーが「A[注文] --> B{在庫ある?}」を読むと、こう呼ばれる
db.addVertex('A', '注文', 'square');
db.addVertex('B', '在庫ある?', 'diamond');
db.addLink(['A'], ['B'], { type: 'arrow_point' });

Jison で作ったパーサーは、文を読みながら記録係のメソッドを呼びます。読み終わると、vertices と edges に図の中身がそろっています。

07置き場所を決める

箱が重ならず、線の交差が少ない並べ方を探します。

コードで見ると：描き係が共通の道具にわたすデータ
// diagrams/flowchart/flowRenderer-v3-unified.ts（短くしたもの）
const data = diag.db.getData();
// data = {
//   nodes: [{ id: 'A', label: '注文', shape: 'rect' }, …],
//   edges: [{ start: 'A', end: 'B', arrowTypeEnd: 'arrow_point' }, …],
// }
data.layoutAlgorithm = getRegisteredLayoutAlgorithm(layout);  // 'dagre' など
data.direction = diag.db.getDirection();                       // 'LR' など
await render(data, svg);   // 測る → 置く → 描く

ノードの配列と線の配列という同じ形にそろえるので、フローチャートでもクラス図でも、同じ render() で描けます。

09色を変える

テーマは 11 種類。

設定は上に重ねたものが勝ちます。

コードで見ると：設定は「上書き」の連続
// config.ts の考え方（本物は入れ子の中まで合わせる assignWithDepth を使う）
let config = { ...siteConfig };      // はじめから＋initialize() の設定

for (const d of directives) {     // 図の中の設定
  sanitize(d);                         // 安全でない項目を消してから
  config = { ...config, ...d };        // あとから来たものが勝つ
}

{ ...a, ...b } は、a のプロパティを b で上書きした新しいオブジェクトを作る書き方です。同じ名前のプロパティは後ろが勝ちます。

11安全のしくみ

図にまぎれた悪いスクリプトを消してから表示します。

直したコードで図が変わっていないか、ロボットが毎回チェックします。

コードで見ると：図の中から安全の設定を変えさせない
// config.ts の sanitize（短くしたもの）
for (const key of ['secure', ...siteConfig.secure]) {
  if (Object.hasOwn(options, key)) {
    delete options[key];   // securityLevel などは消す
  }
}
for (const key of Object.keys(options)) {
  if (key.startsWith('__')) {
    delete options[key];   // __proto__ などを使う攻撃を防ぐ
  }
}

図を書いた人が %%{init: {"securityLevel": "loose"}}%% と書いても、この処理で消されるので、ページを作った人が決めた安全の設定は変わりません。
